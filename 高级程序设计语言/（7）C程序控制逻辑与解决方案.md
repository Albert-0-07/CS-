### **1.4储存期**

​	**变量在内存中存在的时期：**

| 时期           | 说明                                                     |
| -------------- | -------------------------------------------------------- |
| 静态储存期     | 在程序执行期间一直存在，**并且一直保留上一次计算的结果** |
| 线程储存期     | 用于**并发设计**，从被声明到线程结束一直存在             |
| 自动储存期     | 由C标准定义决定其存在时期                                |
| 动态分配储存期 | 由编写程序的人自己控制                                   |

### **2.程序（软件层面）**

​	**该变量在程序中可以被访问的范围**：

| 作用域         | 说明                                                       |
| :------------- | ---------------------------------------------------------- |
| 块作用域       | 从块开始到块结束                                           |
| 函数作用域     |                                                            |
| 函数原型作用域 | 函数原型中的形参名，如：`void f(int n, int m, ar [m][n]);` |
| 文件作用域     | 可见范围作为整个编译单元                                   |

| 链接     | 说明                                                         |      |
| :------- | ------------------------------------------------------------ | ---- |
| 内部链接 | 具有文件作用域的标识符，如果使用`static`关键字修饰，则具有**内部链接**。这意味着它仅在**定义它的那个编译单元内**可见。这是实现“文件作用域”的最常用方式。 |      |
| 外部链接 | 没有用`static`修饰的文件作用域标识符（即普通的全局变量或函数），具有**外部链接**。它在**整个程序的所有编译单元中**都可见（但需要通过`extern`声明来访问）。这是更广的作用域。 |      |
| 无链接   |                                                              |      |

[^编译单元]:  编译器**单次处理**的基本单位。通常是一个源文件加上它通过 `#include` 包含的所有头文件内容。编译器是**一个编译单元接一个编译单元**进行编译的，生成对应的 `.o` 或 `.obj` 目标文件。

### **3.存储类别**

| 存储类别     | 对应变量名称 | 存储期 | 作用域 | 链接 | 声明方式                                                     |      |
| ------------ | ------------ | ------ | ------ | ---- | ------------------------------------------------------------ | ---- |
| 自动         | 自动变量     | 自动   | 块     | 无   | **块内**                                                     |      |
| 寄存器       | 寄存器变量   | 自动   | 块     | 无   | **块内**，使用关键字 `register`                              |      |
| 静态外部链接 | 外部变量     | 静态   | 文件   | 外部 | **所有函数外**。所有**编译单元**都可以访问，但是要加`extern`关键字修饰 |      |
| 静态内部链接 | 静态全局变量 | 静态   | 文件   | 内部 | **所有函数外**，使用关键字 `static`。仅其所属的**编译单元**可以访问它 |      |
| 静态无链接   | 静态局部变量 | 静态   | 块     | 无   | **块内**，使用关键字 `static`                                |      |

[^声明与定义性声明]: **指一个语句，它不仅向编译器“声明”了某个标识符（变量、函数等）的存在和类型，同时还为其“分配了存储空间”或“提供了完整的实现”**
[^其他编译单元]: 这里其实通常指的是其他的函数，**因为C程序本质上就是由功能不同的函数和函数调用构成的**，即控制流程的main()函数和其他功能函数。



```c
// file1.c
int global_var = 10;           // 外部链接：定义， 其他文件可见
static int file_static_var = 5; // 内部链接：定义， 仅本文件可见
extern int extern_var;         // 外部链接：声明， 定义在其他文件

void func() { ... }            // 外部链接：定义， 其他文件可见
static void helper() { ... }   // 内部链接：定义， 仅本文件可见
```

```c
// file2.c
int global_var; // 错误！与file1.c中的global_var定义冲突（重复定义）。
extern int global_var; // 正确！声明， 将引用file1.c的定义。
int extern_var = 20;   // 正确！定义， 满足file1.c中的extern声明。
```

## 二、结构化编程

- **结构化编程的伟大贡献**在于，它证明了：**任何程序逻辑，无论多复杂，都可以由且仅由这三种基本控制结构组合而成**。这就像证明了任何复杂的绘画都可以由三种原色调配出来一样。它让程序从“面条式代码”变成了可分析、可推导的“乐高积木”。
- **任一流程图均可以利用重复与嵌套等价地写成只含可执行语句列（顺序）、判定子句（选择）和迭代构造（循环），并且每种构造只含有一个入口和一个出口。**

| 核心定理    | 对应你的观察                                    | 价值与体现                                                   |
| :---------- | :---------------------------------------------- | :----------------------------------------------------------- |
| **1. 顺序** | `main` 函数中语句的逐行执行；函数体的内部逻辑。 | 提供了**可预测的基本执行流**。                               |
| **2. 选择** | `if`, `switch` 等条件语句。                     | 让程序能根据不同**状态**做出决策，实现了逻辑分支。           |
| **3. 循环** | `for`, `while`, `do-while` 循环。               | 用有限的代码处理重复或不确定次数的任务，实现了**控制流的重复**。 |

[^出口条件循环]: 在循环迭代之后检查测试条件，保证循环至少执行一次
[^入口条件循环]: 在循环的每次迭代之前检查测试的条件，所以有可能根本不执行循环语句中的内容
[^测试]: 指的是在循环体执行前，对**循环条件表达式**进行一次**布尔求值判断**。

## 三、编译预处理指令与大程序结构

### **1.宏与编译过程**

- **用`#define`定义有值的宏**，语法`#define <名字> <值>`
- 定义没有值的宏
- 定义带参数的宏，语法`#define <名字>(参数) (<含参的表达式>)`
- `(<含参的表达式>)`要注意运算优先级的问题，参数的引用要用`()`
- 多行宏定义用`\`隔开

**.c(源文件)->.i(中间处理文件)->.s(中间处理文件)->.o(目标代码文件)->a.out(可执行文件)**

**源文件---->中间结果文件---->中间处理文件---->目标代码文件---->可执行文件**

​          **编译预处理->          编译->                   汇编->                    链接->**

 

### **2.预定义的宏**

#### 1. 环境与文件信息宏

这类宏在调试和生成日志时极其有用。

| 宏             | 描述                                                         | 展开示例/值                               |
| :------------- | :----------------------------------------------------------- | :---------------------------------------- |
| **`__LINE__`** | 展开为当前源代码的**行号**（一个整数常量）。                 | `printf(“Error at line %d\n“, __LINE__);` |
| **`__FILE__`** | 展开为当前源代码的**文件名**（一个字符串常量）。             | `printf(“In file: %s\n“, __FILE__);`      |
| **`__DATE__`** | 展开为编译时的**日期**（格式为 `“Mmm dd yyyy“` 的字符串）。  | `“Apr 26 2024“`                           |
| **`__TIME__`** | 展开为编译时的**时间**（格式为 `“hh:mm:ss“` 的字符串）。     | `“14:30:15“`                              |
| **`__func__`** | 展开为当前所在的**函数名**（C99标准引入）。这是一个**标识符**，而非字符串字面量，但通常当作字符串使用。 | `printf(“In function: %s\n“, __func__);`  |

#### 2. 编译器与架构特性宏

这些宏帮助你编写与编译器或硬件平台相关的代码。

| 宏                     | 描述                                                         |
| :--------------------- | :----------------------------------------------------------- |
| **`__STDC__`**         | 如果编译器遵循ANSI C标准，则被定义为 `1`。用于检查编译环境是否符合标准C。 |
| **`__STDC_VERSION__`** | 表示编译器遵循的C标准版本。例如，C11对应 `201112L`。         |
| **`__cplusplus`**      | **仅在C++编译器中被定义**。在纯C编译器中通常未定义。常用于编写C/C++兼容的头文件。 |

#### 3. 条件编译的实用宏

它们本身没有值，但用于判断是否被定义。

| 宏                                | 描述                                                 |
| :-------------------------------- | :--------------------------------------------------- |
| **`__unix__`** 或 **`__linux__`** | 通常在Unix或Linux系统上被定义。                      |
| **`_WIN32`**                      | 在Windows 32位或64位系统上被定义。                   |
| **`__APPLE__`**                   | 在苹果macOS或iOS系统上被定义。                       |
| **`__GNUC__`**                    | 如果使用GCC编译器，则被定义，其值代表GCC的主版本号。 |
| **`_MSC_VER`**                    | 如果使用微软Visual C++编译器，则被定义。             |

#### 4. 预定义宏 `#pragma` 操作符

虽然不是宏，但`#pragma`是预处理器的一个重要指令，用于向编译器传递特定信息。

```c
#pragma message(“正在编译这个文件...“) // 编译时输出一条消息
#pragma warning(disable: 4996) // 在MSVC中禁用某个警告
#pragma pack(1) // 设置结构体对齐字节数
```

### **3.多文件处理**

#### 1.函数原型与函数实体

1. 函数原型：是函数的声明，即包含函数的返回类型、标识符、参数以及形参类型的语句，

​			语法为`<返回类型> <标识符>(<形参列表>);`

​	     2.函数实体：函数功能具体实现的代码

#### 2.项目

处理多个源文件时，通过构建项目来解决main()函数调用其他源代码文件（.c）问题

#### 3.头文件（.h）

​	1.用来存放函数声明，在需要调用相关函数的源代码文件（.c）中用`#include""`相关头文件

​	一般来说任何.c文件（除了main.c）都应又与之同名的.h文件，用来**声明所有对外公开**的函数原型和全局变量

​	在函数或者变量前面加上`static`修饰使其只能在其所在的编译单元中使用

​	2.只有声明才能被放在头文件中

​	3.函数的定义时定义，函数的原型是声明

​	变量的定义是定义，变量的extern声明是声明

​	4.标准头文件结构与编译原理（.i文件）

## 六、main()函数、入口、控制权与结构化编程

main()函数是C程序的唯一入口，问题的解决是靠main()函数解决的。具体来说通过main()提供一个解决问题的逻辑，即解决问题的方法，或者说是解决问题的过程，这也就是面向过程四个字的来历，通过调用其他函数最终解决问题。而这些被调函数则体现了自顶向下的设计哲学。另外从硬件层面来讲，C程序解决问题的本质就是控制权在不同函数地址之间的转换。
