#                  			**C语言中的一些常识**

##  一、C的历史发展

1. **最初的C语言（K&R C）**：在C语言被发明和早期使用时，其核心只包括了**基本语法、数据类型、运算符、流程控制、函数**等。输入/输出（I/O）这种与**具体操作系统硬件**强相关的功能，被认为**不属于语言核心**。          	**原因如下 ：**

   1. 当时相关软硬件还不那么复杂
   2. 要求高级程序设计语言尽可能地贴近硬件以便尽可能地释放硬件的性能

2. **设计与哲学**：C语言的设计哲学是“**保持核心小而精**”。将I/O功能剥离，使得语言本身更易于移植到不同的计算机系统上。不同系统只需要提供自己的I/O实现（库）即可。

3. **标准库的形成**：那些常用的I/O函数（如 `printf`, `scanf`）被放在一个**标准库**中。它们不是“关键字”，而是预写好的**函数**。这就是为什么你必须写 `#include <stdio.h>` 才能使用它们——你是在引入库的**声明**，而非启用语言的某个内置部分。

4. **成为标准**：后来，随着**ANSI C**和**ISO C**标准的建立，这个**标准库**（包括`<stdio.h>`, `<stdlib.h>`等）被正式纳入了C语言标准体系，成为“符合C标准的实现”所**必须提供**的部分。从此，我们说“C语言”就包括了**核心语言**和**标准库**两部分。

   ![](pictures/deepseek_mermaid_20251228_cb624e (1).png)

   [^ANSI]: 全称：American National Standards Institute（美国国家标准协会）是成立于1918年的非营利性民间标准化组织，总部设于纽约。其前身为美国工程标准委员会（AESC），经1928年、1966年两次改组后于1969年采用现名。该组织的成立源于当时美国各行业标准化工作缺乏协调导致的多方矛盾，数百个科技团体共同推动建立统一协调机构。成员涵盖约200个行业协会及1400家公司，经费来源于会费与标准销售，负责协调政府部门与民间标准化活动，指导并审核美国国家标准的制定与发布。
   [^ISO]: 全称：International Organization for Standardization（国际标准化组织）成立于1947年，是标准化领域中的一个国际组织，该组织自我定义为[非政府组织](https://baike.baidu.com/item/非政府组织/1416088?fromModule=lemma_inlink)，官方语言是英语、法语和俄语。ISO一来源于希腊语“ISOS”，其意为“平等”。
   [^ISO]: ISO负责当今世界上多数领域（包括军工、石油、船舶等[垄断行业](https://baike.baidu.com/item/垄断行业/6999603?fromModule=lemma_inlink)）的标准化活动，通过2856个技术结构（含技术委员会611个、工作组2022个、特别工作组38个）开展技术活动。
   [^ISO]: 全体大会是ISO最高权力机构；理事会是ISO重要决策机构；中央秘书处是ISO日常办事机构，设在瑞士日内瓦，现有170名职员，由秘书长领导。

## 二、C实现与C标准

### **1.C实现——C编译器与IDE：**

| 特征         | **最初的C编译 (1970s)**                                    | **现代IDE编译**                                    |
| :----------- | :--------------------------------------------------------- | :------------------------------------------------- |
| **界面**     | 命令行终端，纯文本。                                       | 图形化集成开发环境。                               |
| **过程**     | **手动、分步**，清晰但繁琐。                               | **全自动、一键完成**，隐藏细节。                   |
| **反馈**     | 错误信息打印到终端，需手动翻看。                           | 错误在编辑器中**实时高亮**，点击跳转。             |
| **输出**     | 默认的、无意义的 `a.out`。                                 | 可定制的、有意义的可执行文件名。                   |
| **调试**     | 使用原始的 `adb` 或 `sdb`，类似在黑暗中摸索。              | 图形化调试器，可设置断点、监视变量、查看调用栈。   |
| **核心精神** | **程序员必须理解整个工具链**，从代码到机器码的每一步转化。 | **程序员专注于业务逻辑**，工具负责底层转化和优化。 |

### **2.C语言标准演进史**

| 标准名称               | 制定年份/机构                     | 历史地位与核心贡献                                           | 主流编译器支持情况                                           |
| :--------------------- | :-------------------------------- | :----------------------------------------------------------- | :----------------------------------------------------------- |
| **K&R C**              | 1978年（《C程序设计语言》第一版） | **事实标准**。C语言的起源，但未正式标准化，特性依赖于实现。  | 无现代编译器完全遵循，仅具历史意义。                         |
| **ANSI C / C89 / C90** | 1989年ANSI / 1990年ISO采纳        | **第一个官方标准，是C语言的基石**。统一了语法和行为，定义了标准库。至今仍是“经典C”的代名词。 | **所有**现代编译器都完全支持，是**最低限度的通用子集**。     |
| C94/C95                | 1995年ISO                         | 对C90的修订和扩展，主要增加了**宽字符和多字节字符**支持。    | 被后续标准吸收，主流编译器均支持。                           |
| **C99**                | 1999年ISO                         | **里程碑式的重大更新**。引入了： • 单行注释 `//` • 变量声明不必在作用域开头 • 新的数据类型（`long long`、`_Bool`、复数） • 变长数组 • 灵活数组成员 • `inline` 关键字 | **GCC和Clang早已完全支持**。 **MSVC（Visual Studio）长期仅部分支持**，直到VS2019才宣布“基本完成”。这是Windows/Linux开发的一个重要差异点。 |
| **C11**                | 2011年ISO                         | 现代化更新，强调安全与多线程。 • `_Generic` 关键字（泛型选择） • `_Static_assert` • 边界检查函数（可选） • 原生多线程支持（`<threads.h>`） | **GCC和Clang完全支持**。 **MSVC支持大部分核心特性**，但多线程库等部分支持不完整。 |
| **C17/C18**            | 2018年ISO                         | **缺陷修补版**。未引入新特性，仅修正了C11中的缺陷和模糊之处。因此，C11和C17常被视作同一代标准。 | 被当前所有活跃维护的编译器视为最新的稳定标准。               |
| **C23**                | 预计2023年发布                    | **下一个重要版本**。预计将移除过时特性，并引入： • `#embed`（嵌入二进制资源） • 新的属性语法 • 强化布尔类型和枚举 | 目前，**GCC和Clang已在开发版本中开始实验性支持**部分特性。   |

## 三、格式化输入输出来历

- 让计算机知道处理数据的类型和方法
- 在C语言中，变量只是一段内存。`printf("%d", a)` 中的 `%d` 起到了**关键的双重作用**：

1. **类型解释器**：告诉函数，“请将变量 `a` 所在**内存的二进制位**，**解释为一个有符号整数**”。
2. **序列化协议**：规定如何将这个整数**转换（序列化）** 成人类可读的字符序列（比如将二进制 `1101` 变成字符 `"13"`）。

如果没有格式符，计算机面对内存中的 `0x0000000d` 时，无法知道它应该被显示为整数 `13`、字符 `'\r'` 还是某个浮点数的极小部分。

## 四、不同高级程序设计语言的设计哲学

**追求最大程度释放硬件性能     （C++）  追求安全、可靠、可团队协作（简单，易读）**

| 追求最大程度释放硬件性能 | 追求安全、可靠、可团队协作（简单，易读） |
| :----------------------- | ---------------------------------------- |
| 操作系统                 |                                          |
| C语言                    | java，python，GO，JS                     |

**设计哲学的演变**：

- **C语言**：信任程序员，赋予最大控制权和责任，追求极致效率和透明。
- **现代高级语言**：追求开发效率、安全性和可读性，通过**类型系统、重载、多态**等机制，让编译器承担更多类型匹配的职责，防止人为错误。

## **五、不同编程语言的特点**

|      语言      | **核心范式/特点**                                 | **绝对优势领域（最佳应用场景）**                             | **关键权衡与考量**                                           |
| :------------: | ------------------------------------------------- | :----------------------------------------------------------- | :----------------------------------------------------------- |
|     **C**      | 过程式、贴近硬件、手动内存管理                    | 操作系统内核、嵌入式固件、对体积和性能有极致要求的基础库。   | **极致控制 ↔ 极高责任**。开发效率低，安全性完全依赖开发者。  |
|    **C++**     | 多范式（面向对象、泛型、过程式）、零成本抽象      | 游戏引擎、高频交易系统、浏览器/数据库核心、CAD/科学计算。    | **强大灵活 ↔ 极端复杂**。需要极高技能才能驾驭，错误成本高。  |
|    **Rust**    | 系统级、编译时所有权担保内存与并发安全            | 对安全性和性能有双重要求的系统软件（OS、浏览器组件、安全关键服务）、基础工具链。 | **安全可控 ↔ 学习曲线陡峭**。开发体验现代，但所有权概念需要适应。 |
|    **Java**    | 面向对象、跨平台JVM、托管运行、强大的生态系统     | 大型企业级后端服务、Android应用、大数据处理框架。            | **“一处编写，处处运行” ↔ 运行时开销**。生态成熟但相对笨重，启动慢。 |
|     **Go**     | 简单语法、原生并发（goroutine）、编译为单一二进制 | 云原生/微服务、API网关、命令行工具、 DevOps工具。            | **开发效率与并发友好 ↔ 抽象层次较低**。擅长并发I/O，但缺乏泛型等高级抽象。 |
|   **Python**   | 动态类型、解释执行、极简语法、胶水语言            | 数据科学/AI/ML、快速原型、Web后端、自动化脚本、教育。        | **开发速度极快 ↔ 运行时慢**。全局解释器锁限制多核CPU并行。   |
| **JavaScript** | 事件驱动、非阻塞I/O、单线程（浏览器）             | 所有前端Web交互、使用Node.js的全栈开发、跨平台桌面应用。     | **事实上的Web标准 ↔ 动态类型风险**。异步编程模型独特，生态庞大但碎片。 |
